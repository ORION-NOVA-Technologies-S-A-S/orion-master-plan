## 1. Objetivo

Esta política establece las reglas para identificar, proteger, utilizar, licenciar y transferir los activos de propiedad intelectual relacionados con Orion Nova Technologies.

Busca proteger:

* Software.
* Código fuente.
* Aplicaciones.
* Páginas web.
* Sistemas empresariales.
* Modelos y soluciones de inteligencia artificial.
* Diseños.
* Documentación.
* Manuales.
* Bases de datos creativas.
* Contenido audiovisual.
* Logotipos.
* Nombre comercial.
* Personajes de marca.
* Metodologías.
* Información confidencial.
* Materiales entregados por clientes.

Esta política es una guía interna y deberá complementarse con contratos y revisión jurídica cuando sea necesario.

---

## 2. Titularidad e identificación

Orion Nova Technologies es un establecimiento de comercio de propiedad de una persona natural y no una persona jurídica independiente.

Por esta razón, los documentos de propiedad intelectual deberán identificar correctamente a:

> **Carlos Daniel Culma Perdomo**, persona natural comerciante y propietario del establecimiento de comercio Orion Nova Technologies.

El nombre comercial podrá utilizarse para identificar los productos y servicios, pero los contratos y registros deberán indicar claramente la persona natural que actúa como autor, titular, licenciante o cesionario.

## 3. Principios

La gestión de propiedad intelectual se basará en:

* Respeto por los derechos de terceros.
* Reconocimiento de la autoría.
* Uso de software con licencias válidas.
* Definición escrita de los derechos.
* Protección del código y la información.
* Transparencia con clientes y colaboradores.
* Autorización para utilizar marcas y contenidos.
* Registro de las contribuciones humanas.
* Uso responsable de inteligencia artificial.
* Conservación de evidencias de creación.

## 5. Software desarrollado internamente

El software desarrollado directamente por el propietario para Orion Nova Technologies será administrado como un activo intelectual, siempre que:

* No haya sido creado bajo un contrato que entregue los derechos a un tercero.
* No incorpore código sin licencia.
* No contenga información confidencial de un cliente.
* Se pueda demostrar el proceso de creación.
* Se identifiquen correctamente los colaboradores.
* Se documenten los componentes externos utilizados.

La evidencia podrá incluir:

* Historial de Git.
* Fechas de commits.
* Repositorios.
* Diagramas.
* Documentos de requisitos.
* Prototipos.
* Manuales.
* Copias de seguridad.
* Versiones publicadas.
* Contratos con colaboradores.
* Registros ante autoridades.

La protección del derecho de autor nace con la creación de la obra. El registro ante la Dirección Nacional de Derecho de Autor es declarativo, voluntario y puede servir como evidencia de titularidad.

## 6. Proyectos desarrollados para clientes

Antes de comenzar un proyecto se deberá definir por escrito:

* Quién aporta la idea y los materiales.
* Quién desarrollará el código.
* Quién será el titular de los derechos patrimoniales.
* Si el cliente recibirá una licencia o una cesión.
* Si se entregará el código fuente.
* Qué componentes podrá reutilizar Orion Nova Technologies.
* Qué elementos pertenecen a terceros.
* Qué usos podrá realizar el cliente.
* Si el proyecto podrá aparecer en el portafolio.
* Qué ocurrirá si no se completa el pago.

Los derechos no deberán dejarse definidos únicamente mediante conversaciones verbales.

## 7. Licencia y cesión

| Modalidad                        | Descripción                                                                                                       |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Licencia de uso                  | El cliente puede utilizar la solución bajo condiciones determinadas, pero no recibe necesariamente la titularidad |
| Cesión de derechos patrimoniales | Se transfieren al cliente los derechos especificados en el contrato                                               |
| Desarrollo compartido            | Cada parte conserva o recibe determinados derechos                                                                |
| Software como servicio           | El cliente utiliza la plataforma mediante una suscripción                                                         |
| Código abierto                   | El software se publica bajo una licencia expresamente seleccionada                                                |

En una licencia o cesión se deberá establecer:

* Derechos concedidos.
* Modalidades de uso.
* Territorio.
* Duración.
* Exclusividad o no exclusividad.
* Posibilidad de modificar.
* Posibilidad de distribuir.
* Entrega del código fuente.
* Derechos sobre futuras versiones.
* Condiciones económicas.

La cesión de derechos patrimoniales debe constar por escrito. La DNDA también indica que los actos o contratos de transferencia pueden inscribirse para publicidad y oponibilidad frente a terceros.

La transferencia o licencia acordada solamente se hará efectiva después del pago total, salvo que el contrato disponga expresamente algo diferente.

## 8. Componentes preexistentes

Orion Nova Technologies podrá utilizar componentes creados antes de un proyecto, como:

* Plantillas.
* Módulos.
* Librerías internas.
* Funciones genéricas.
* Estructuras de proyecto.
* Herramientas.
* Metodologías.
* Componentes de seguridad.
* Sistemas de autenticación.
* Diseños reutilizables.

Estos componentes no se transferirán automáticamente al cliente.

El contrato deberá conceder únicamente los permisos necesarios para utilizar dichos componentes dentro del proyecto entregado.

---

## 9. Componentes de terceros y código abierto

Antes de utilizar una dependencia se deberá revisar:

* Nombre.
* Autor o proveedor.
* Versión.
* Tipo de licencia.
* Compatibilidad con uso comercial.
* Obligación de atribución.
* Obligación de publicar modificaciones.
* Restricciones de distribución.
* Riesgos de seguridad.
* Estado de mantenimiento.

Cada repositorio deberá incluir, cuando corresponda:

```text
LICENSE
NOTICE
THIRD_PARTY_NOTICES.md
DEPENDENCIES.md
```

Publicar un repositorio no significa automáticamente que sea software de código abierto. Para conceder permisos deberá seleccionarse e incluirse una licencia.

No se utilizarán:

* Librerías sin licencia conocida.
* Software pirata.
* Plantillas descargadas ilegalmente.
* Imágenes sin autorización.
* Música protegida sin permiso.
* Tipografías sin licencia comercial.
* Código copiado sin atribución o autorización.

## 10. Repositorios

Los repositorios se clasificarán como:

### Públicos

Podrán contener:

* Proyectos demostrativos.
* Documentación institucional.
* Plantillas vacías.
* Código autorizado.
* Material educativo.
* Proyectos bajo licencia definida.

### Privados

Deberán contener:

* Código de clientes.
* Sistemas internos.
* Credenciales protegidas.
* Configuraciones.
* Documentos contractuales.
* Información comercial.
* Vulnerabilidades.
* Proyectos sin autorización pública.

Nunca se publicarán:

* Contraseñas.
* Tokens.
* Claves de API.
* Certificados privados.
* Bases de datos reales.
* Datos personales.
* Código confidencial.
* Contratos firmados.
* Informes de seguridad.

Cada repositorio deberá incluir un `README.md` que indique:

* Nombre del proyecto.
* Titular.
* Autores.
* Licencia.
* Uso permitido.
* Restricciones.
* Dependencias.
* Datos de contacto.

## 14. Inteligencia artificial

Los resultados generados exclusivamente por una herramienta de inteligencia artificial pueden presentar limitaciones de protección. La DNDA sostiene que los resultados generados por IA no son registrables cuando no son producto de una creación humana, pues reconoce como autores a personas físicas.

Por esta razón, Orion Nova Technologies deberá:

* Documentar los aportes humanos.
* Conservar bocetos y versiones.
* Registrar las modificaciones realizadas.
* Revisar las condiciones de la herramienta.
* Verificar si el resultado puede utilizarse comercialmente.
* Evitar solicitar imitaciones de artistas o marcas.
* No ingresar código confidencial sin autorización.
* Revisar posibles coincidencias con obras existentes.
* No prometer exclusividad absoluta sobre contenido puramente generado por IA.

El uso de IA como herramienta de apoyo no elimina la necesidad de revisar la originalidad y los derechos sobre el resultado.

* Territorio.

* Declaración de originalidad.

* Bases de datos.
* Música.
* Marcas.

## 17. Portafolio y publicidad

Un proyecto de cliente solamente podrá mostrarse cuando:

* Exista autorización.
* Haya sido publicado oficialmente.
* Se oculten credenciales y datos personales.
* No se revelen secretos empresariales.
* No se exponga código privado.
* Se respeten las condiciones del contrato.

La autorización deberá indicar si se puede utilizar:

* Nombre del cliente.
* Logotipo.
* Capturas.
* Video.
* Descripción.
* Resultados.
* Testimonio.

## 18. Registro de software

Orion Nova Technologies podrá registrar ante la DNDA sus desarrollos propios más importantes.

Según la DNDA, para registrar software pueden aportarse elementos como código fuente, descripción del programa o material auxiliar, como manuales.

Antes del registro se verificará:

* Nombre de la obra.
* Autor o autores.
* Titular.
* Año de creación.
* Estado de publicación.
* Componentes de terceros.
* Contratos de cesión.
* Versión registrada.
* Material que será entregado.

No se registrará como propio un software que pertenezca contractualmente a un cliente, empleador o institución.

## 21. Uso no autorizado

Cuando se identifique un posible uso no autorizado se deberá:

1. Conservar evidencias.
2. Registrar fecha, URL y capturas.
3. Identificar el activo afectado.
4. Revisar los contratos y licencias.
5. Evitar confrontaciones o accesos indebidos.
6. Consultar asesoría jurídica.
7. Solicitar retiro o corrección por el canal adecuado.
8. Utilizar los mecanismos de la plataforma cuando corresponda.
9. Informar a la autoridad competente si resulta necesario.

No se eliminarán evidencias ni se intentará ingresar a sistemas de terceros.
